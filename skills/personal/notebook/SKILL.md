# Notebook

The notebook is a vault of working documents, organized by topic. Dated notes are the record: written once, named by timestamp and kind. Each topic folder has one living page, the synthesis of its notes, revised as they land. A new session reads the page, not the pile.

This skill alone owns vault paths. Other skills name a note's `type` and file it here.

## Path

Resolve the vault root once per task:

```sh
NOTEBOOK="${AI_NOTEBOOK_PATH:-$HOME/Notebook}"
```

Every path below is relative to `$NOTEBOOK`. When the root is missing, create it: `mkdir -p "$NOTEBOOK"/{topics,inbox,archive/topics,archive/legacy,_bulk}`, then an empty `index.md` and `log.md`.

Durable project docs belong in the repo and follow their own convention: `GLOSSARY.md`, ADRs, `README`, `AGENTS.md`, `CLAUDE.md`, skills.

## Layout

| Path | Holds |
|---|---|
| `topics/<slug>/` | One folder per ticket or standalone topic: its page `<slug>.md`, its notes, and `artifacts/` |
| `inbox/` | One-off notes with no ticket and no clear topic, flat |
| `archive/topics/<slug>/` | Finished topic folders, moved whole |
| `archive/legacy/` | Frozen notes from before the topic layout |
| `_bulk/<slug>/<stamp>-<name>/` | Anything over 1 MB, any binary (screenshots, recordings, profiles), and raw captures (HTTP dumps, traces, tool caches). Untracked by git and unsynced |
| `index.md` | Router: one line per topic page |
| `log.md` | Append-only record of compile ingests |
| `lint.md` | Generated by `notebook-lint`; read it, never edit it |
| `backlog.md` | Parked work (see Backlog) |
| `scripts/` | The vault's sync script and git hooks |

The root is closed: anything else there is a lint error. Git holds notes and small text artifacts only; the pre-commit hook rejects big, binary and raw files outside `_bulk/`.

- **Slug**: lowercase kebab-case, ticket id first when there is one (`eng-1006-stuck-jobs`).
- **Folder**: create it with the first note that carries a ticket or a clear topic. Two inbox notes on the same slug get promoted into a topic folder.
- **Epic**: a multi-ticket effort gets its own folder (`topics/<epic>/`) for cross-ticket notes and a page that routes to its ticket folders. Each ticket's page sets `parent: <epic>`. Ticket folders stay flat beside it, never nested inside.

## Naming

- Stamp: run `date +%Y-%m-%d-%H%M`. Read it from the command, every time.
- Note: `<stamp>-<kind>-<desc>.md`, lowercase kebab-case, with `<kind>` equal to its `type` (`2026-09-29-2240-research-queue-lock-contention.md`).
- Artifacts: `topics/<slug>/artifacts/<stamp>-<name>/`, small text only (json, txt, sh, log, patch, sql). Files keep their own names inside it. Reuse the note's folder when it exists.
- Page: `topics/<slug>/<slug>.md`, revised in place, never re-stamped.

## Frontmatter

Every note:

```yaml
type: research      # research | plan | decision | grill | deploy | review | report | prototype | handoff | draft
topic: eng-1006-stuck-jobs   # the folder slug; `inbox` for inbox notes
tickets: [ENG-1006]          # empty list when none
status: active      # active | superseded | done
supersedes: "[[2026-09-28-1810-handoff-stuck-jobs-triage]]"   # optional
```

Every topic page:

```yaml
type: topic
status: active      # active | parked | done
parent: <epic>      # optional
tickets: [ENG-1006]
```

`draft` covers unfinished writing and anything no other type fits. A `report` is a standalone HTML or CSV deliverable; a `review` is a code or PR review.

## Writing

1. Pick the `type`, then the folder: the topic's, or `inbox/`. Search first (see Reading); a new ticket or topic gets its folder and page now.
2. Run `date` for the stamp, name the file, write the frontmatter.
3. Link notes with a wikilink on the stem, `[[2026-09-29-2240-research-queue-lock-contention]]`, and files with a vault-relative path, `topics/eng-1006-stuck-jobs/artifacts/2026-09-29-2240-audit/locks.txt` or `_bulk/eng-1006-stuck-jobs/2026-09-29-2240-heap/`.
4. Reference specs, PRs and issues by URL or path. Keep their content out of the note.
5. Redact keys, passwords and personal data before saving. Values from `_bulk/` stay there; the note summarizes them.
6. Add the note to its page's Sources. A handoff also sets `status: superseded` on the one it replaces, `supersedes:` on itself, and points the page's **Resume** line at itself. Fold the note's findings into State, Decisions and Open when they are quick to place; otherwise the next compile does it.

## Topic page

The page is the one place a claim about the topic is kept current. Its notes are the sources: the page cites them and is rewritten as they accumulate.

- **Resume** line, first under the title: `**Resume**: [[<newest active handoff>]]`, or `none`.
- **State**: what is known now, each claim followed by the wikilink of the note that backs it.
- **Decisions**: what was decided and why, newest first.
- **Open**: unanswered questions and threads not yet picked up.
- **Sources**: a wikilink per note in the folder, newest first, one line each.

`index.md` routes to every page, grouped Active / Parked / Recently archived, one line of at most 120 characters saying what the topic is, never its status: `- [[eng-1006-stuck-jobs]]: jobs stuck in the queue worker`. Add the line when the page is created.

A lookup that synthesizes several notes to answer a question is itself a finding: write it into the page, so the next session reads it there instead of rebuilding it.

## Backlog

`backlog.md` holds parked work: researched or designed, with a handoff written, and not being done now. One entry per item, newest first: when parked and why, the note to resume from, the first action, and the topic page. Park there whenever a session ends with a handoff nobody is picking up, and set the page to `status: parked`. When the item starts, delete its entry and set the page back to `active`.

## Reading

Read down the ladder: `index.md`, then the topic page, then the notes it cites. Filenames sort chronologically, so `ls "$NOTEBOOK/topics/<slug>" | tail` is the topic's recent history.

- **Ticket or topic**: its `index.md` line, then the page. With no line, `grep -rli "eng-1006" "$NOTEBOOK/topics" "$NOTEBOOK/inbox" --include='*.md'`.
- **Continuing work**: the page's Resume note, then Open and Decisions. Parked work: its `backlog.md` entry, then the note it names.
- **By kind**: `grep -rl '^type: grill' "$NOTEBOOK/topics"`; add `--include` or a folder to narrow it.
- Obsidian's index skips `archive/`, `_bulk/` and every `artifacts/`, so search those with grep.

Pre-restructure notes live frozen in `archive/legacy/<old dir>/`, under the old dirs by kind (`research/`, `plans/`, `decisions/`, `reviews/`, `prototypes/`, `handoff/`, `drafts/`), without frontmatter. Search there when the topic tree has nothing. Re-file a legacy note only when it is first needed: `git mv` it into its topic folder under a `<stamp>-<kind>-<desc>.md` name, add frontmatter, rewrite links to its old stem, and add it to Sources.
